## 六、关键约定与已知坑

### 6.1 接口冻结（10-22 10:30 后只加不改）

1. `X-Cache` 只能是 `HIT / MISS / REVALIDATED`；`X-Edge` 是 `A / B`。
2. 每个服务都有 `/stats`（JSON）与 `/health`（`ok`）。
3. `/stats` 字段：`requests, hits, misses, revalidated, evictions, bytes_from_origin, bytes_to_client, inflight, cache_entries, cache_capacity, hit_ratio`。
4. 控制端点：边缘 `/admin/clear`、`/admin/delay?ms=`、`/admin/capacity?n=`；源站 `/admin/max-age?seconds=`、`/admin/delay?ms=`；调度器 `/admin/edges`、`/admin/down?edge=`、`/admin/up?edge=`。
5. 端口：源站 `127.0.0.1:9000`；边缘 `127.0.0.1:8000`(A) / `127.0.0.2:8000`(B)；DNS `udp 127.0.0.1:5353`；控制台 `127.0.0.1:8053`。

### 6.2 E5 必须改设计（B 负责）

现状是「10 个对象顺序打 30 次」，大部分 MISS，多了一跳，会得出“边缘比直连源站慢”的**反向结论**。改成：

1. 预热：3 个热点对象各请求一次；
2. 再对 3 个热点对象重复请求 33 次（共 99 次）；
3. 同一请求序列分别打「直连源站（`/admin/delay?ms=50`）」与「经边缘」；
4. 报告里写明**为什么这样设计**（CDN 收益来自命中，不是首次请求）——这本身是加分点。

### 6.3 单机演示的物理限制（要写进报告第 8 节）

回环网络没有真实链路时延，所以必须用 `/admin/delay?ms=50` 人为制造“源站离用户远”。这不是造假，而是**受控实验**：报告里说明“用服务端注入时延模拟传播时延，边缘命中不经过该路径”，并给出实测与理论（`2×RTT + 传输时间`）的对照。
